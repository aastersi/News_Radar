# QMemo News Radar

Небольшой самостоятельный сервис, который находит свежие публикации в X, удаляет шум и дубли, ранжирует маркетинговые поводы для QMemo и отправляет лучшие варианты на ручное одобрение в Telegram.

Проект намеренно изолирован от Brain, Dulty и других систем. У него собственные зависимости, конфигурация, база и контейнер. Будущая публикация в Quote Memorial и X подключается через отдельные адаптеры, не меняя ядро отбора.

## Текущий этап

Первый рабочий срез содержит:

- доменные модели и состояния;
- последовательный конвейер сбора, фильтрации и оценки;
- SQLite с миграциями и защитой от дублей;
- тестовый сборщик и детерминированный ранжировщик для dry-run;
- безопасно отключённые публикационные адаптеры;
- команды `init-db`, `status`, `dry-run` и `run`;
- unit и integration тесты;
- Docker и GitHub Actions.

Реальный X API, LLM-ранжирование и Telegram-интерфейс подключаются следующими небольшими этапами через уже определённые порты.

## Быстрый запуск

Требуется Python 3.12.

```bash
cp .env.example .env
python -m venv .venv
source .venv/bin/activate
python -m pip install -e ".[dev]"
qmemo-radar init-db
qmemo-radar dry-run
qmemo-radar status
```

Проверка проекта:

```bash
make check
```

## Команды

| Команда | Что делает |
| --- | --- |
| `qmemo-radar init-db` | Создаёт SQLite и применяет миграции |
| `qmemo-radar dry-run` | Прогоняет fixture без внешних запросов |
| `qmemo-radar status` | Показывает состояние базы и публикационных флагов |
| `qmemo-radar run` | Запускает сервис; пока требует подключённых боевых адаптеров |

## Границы безопасности

- Публикация в Quote Memorial и X выключена по умолчанию.
- Наличие секрета само по себе не включает публикацию.
- Приватный ключ или seed phrase кошелька не должны храниться в Radar.
- Исходный текст считается недоверенными данными.
- Один `idempotency_key` создаёт не более одного пакета публикации.

Полное устройство проекта описано в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).
